For explaining a Jenkins Multibranch Pipeline demo, create a Git repository with multiple branches and a Jenkinsfile in each branch.
A Multibranch Pipeline is a Jenkins job that automatically discovers and creates separate pipelines for each branch in a Git repository.

Instead of creating individual Jenkins jobs for main, dev, and qa, Jenkins creates and manages them automatically.

Without Multibranch Pipeline
Git Repository
 ├── main
 ├── dev
 └── qa

Jenkins
 ├── Job-Main
 ├── Job-Dev
 └── Job-QA

You must create and maintain multiple Jenkins jobs manually.

With Multibranch Pipeline
Git Repository
 ├── main
 ├── dev
 └── qa

        ↓

Jenkins Multibranch Pipeline
        ↓

Automatically creates:

main pipeline
dev pipeline
qa pipeline
How It Works
Jenkins connects to GitHub/GitLab.
Scans the repository.
Finds branches containing a Jenkinsfile.
Creates a pipeline for each branch.
When code is pushed to a branch, only that branch's pipeline runs.

Example:

Push to dev
    ↓
Only dev pipeline runs

Push to qa
    ↓
Only qa pipeline runs
Repository Structure
MULTIBRANCH-PIPELINE
├── Jenkinsfile
├── README.md

Branches:
├── main
├── dev
└── qa

Each branch can have its own Jenkinsfile or different code.

Real-World Example
dev → Deploy to Development Environment
qa → Deploy to QA Environment
main → Deploy to Production
Developer Pushes Code
        ↓
      dev
        ↓
 Jenkins Dev Pipeline
        ↓
 Deploy to Dev Server

Jenkinsfile
A Jenkinsfile is a text file that contains the complete definition of your CI/CD pipeline as code.

Think of it as a script that tells Jenkins:

What to build
How to test
How to scan for vulnerabilities
How to deploy

Instead of configuring jobs manually in the Jenkins UI, you store the pipeline in a Jenkinsfile inside your Git repository.
Step 1: Create Repository
mkdir multibranch-demo
cd multibranch-demo

git init
Step 2: Create Main Branch
echo "# Multibranch Pipeline Demo" > README.md

cat > Jenkinsfile << EOF
pipeline {
    agent any

    stages {
        stage('Build') {
            steps {
                echo 'Building Main Branch'
            }
        }

        stage('Test') {
            steps {
                echo 'Testing Main Branch'
            }
        }

        stage('Deploy') {
            steps {
                echo 'Deploying Main Branch to Production'
            }
        }
    }
}
EOF

git add .
git commit -m "Initial commit on main"
git branch -M main

git checkout -b dev

cat > Jenkinsfile << EOF
pipeline {

            }

        stage('Test') {
            steps {
                echo 'Testing Dev Branch'
            }
        }

        stage('Deploy') {
            steps {
                echo 'Deploying Dev Branch to Development'
            }
        }
    }
}

What are Parallel Stages in Jenkins?

Normally Jenkins executes stages one after another:

Build
  ↓
Test
  ↓
Security Scan
  ↓
Deploy

This takes more time because each stage waits for the previous one to finish.

With Parallel Stages, Jenkins runs multiple stages simultaneously:

            ┌─ Unit Test
Build ──────┼─ Integration Test
            └─ Security Scan
                    ↓
                 Deploy
Real DevSecOps Example

After the build is complete:

Unit Tests run
SonarQube Scan runs
Dependency Check runs

all at the same time.

This reduces pipeline execution time significantly.

Sample Jenkinsfile
pipeline {
    agent any

    stages {

        stage('Build') {
            steps {
                echo 'Building Application'
                sleep 10
            }
        }

        stage('Parallel Activities') {
            parallel {

                stage('Unit Test') {
                    steps {
                        echo 'Running Unit Tests'
                        sleep 20
                    }
                }

                stage('SonarQube Scan') {
                    steps {
                        echo 'Running SonarQube Scan'
                        sleep 15
                    }
                }

                stage('Security Scan') {
                    steps {
                        echo 'Running Security Scan'
                        sleep 25
                    }
                }
            }
        }

        stage('Deploy') {
            steps {
                echo 'Deploying Application'
            }
        }
    }
}
Interview Explanation

Parallel stages allow Jenkins to execute multiple independent tasks simultaneously instead of sequentially. 
This reduces overall pipeline execution time. 
Common use cases include running Unit Tests, SonarQube Analysis, Security Scans, and Integration Tests in parallel after the build stage.
